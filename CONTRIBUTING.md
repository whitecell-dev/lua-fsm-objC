# Contributing to CALYX (Lua Edition)

> **Style rules are automated wherever possible. Runtime guarantees are tested.
> Exceptions are explicit. No cleanup should silently change the execution contract.**

This repo is pure Lua (no `.m`/`.h` files). Its conventions are a **Lua port** of
the principles in the [NYTimes Objective-C Style Guide](https://github.com/nytimes/objective-c-style-guide)
(archived 2023, deprecated) -- not literal conformance to it. That guide is a
source of ideas; `stylua.toml` + `.luacheckrc` + the test suite are the standard.
Where the guide has no Lua meaning, it is marked N/A below rather than imitated.

## 1. What carries over from the NYTimes guide

| Guide section | Lua-port rule | Enforced by |
|---|---|---|
| Spacing (4-space indent, braces, 1 blank line between methods) | Tabs, 1 tab/level; `column_width = 120`; 1 blank line between functions | StyLua |
| Naming (long, descriptive; `NYT` prefix) | Descriptive names; `CALYX_` prefix for shared constants; event/state names must match `ABI.PATTERNS` once constructor validation lands | luacheck + review (validation: next pass) |
| Methods (colon/`self` convention) | **Public FSM methods are colon-declared (`function api:can(...)`) because every caller uses colon syntax.** The `can`/`is` silent-`false` bug (2026-10-07) is why this is a correctness rule, not taste | Regression test (next pass) |
| Error handling (switch on the return, not the error var) | `local ok, res = try(); if not ok then handle` using the `ABI.error_result` shape `{ok, code, message, details, tick}`. Never report `{ok=true}` after an ignored error return | Regression test (next pass) |
| Constants over magic literals | Constants near the responsibility that owns them. Only genuinely shared ABI values (states, error codes, patterns) live in `core/abi.lua`. Do not hoist every numeric literal into `abi.lua` -- that hides ownership | Review |
| Booleans (never `== YES`) | Never `== true` / `== false`; use truthiness (`if ok`, `if not err`) | Review |
| Comments (why, not what; delete stale ones) | Explain **why**; keep `KNOWN:`/`FIX:` markers accurate; delete stale comments instead of letting them lie. Reports in `survival_reports/` are regenerated, never hand-edited | Review |
| Private Properties (class extension) | Closure locals + frozen proxy (`__newindex` guard + `__metatable`). No `rawset` escape hatches in new code | Review |
| Categories (prefixed extensions) | Modules extending shared tables prefix additions with `CALYX_`/`calyx_` to avoid collisions (cf. event named `send` clobbering `send()`) | Review |
| Protocols (sender is first param) | Delegate/callback signatures take the sender first: `callback(fsm, ctx)` -- already the dispatcher convention | Regression test (arities) |
| Singletons (`dispatch_once`) | One-time init behind an explicit guard; no reseeding global PRNG per construction; no shared global counters without documentation (`ABI.clock` is process-wide -- see KNOWN) | Review |
| Imports (grouped) | Grouped `require` header: stdlib / bundle (`abi`, `core`, ...) / local. Bare `require("abi")` names resolve only via `package.preload` aliases from `calyx_bundle.lua` (see README) | Review |
| Init ordering | Constructor builds private state, then callbacks, then public API, then freeze -- in that order (cf. `core/objc.lua`) | Review |

Explicitly N/A (Objective-C-only, do not port): dot-notation syntax, `NS_ENUM` /
`NS_OPTIONS`, `CGRect`/`CGGeometry` accessors, image naming, Xcode project
groups, `Treat Warnings as Errors` build setting (luacheck + StyLua gates cover it).

## 2. Toolchain (all Docker-or-local, all runnable from repo root)

```sh
# Lint -- informational until the gate lands; 74 warnings is the post-tightening baseline
luacheck .                        # see BASELINE_LINT.md for classification

# Format CHECK only (this phase changes no sources):
docker run --rm --entrypoint /stylua \
  -v "$PWD:/work" -w /work johnnymorganz/stylua:2.6.0 \
  --check --output-format=summary .
# NOTE: the image has no shell and no default entrypoint -- `--entrypoint /stylua`
# is required. Config comes from ./stylua.toml; ./calyx_bundle.lua is excluded
# via ./.styluaignore (it is generated AND unparseable -- see below).

# Regenerate the bundle after editing core/ (the bundle embeds core/*.lua verbatim):
lua bundler.lua

# Tests -- no aggregate runner; every require is root-relative, run from root:
lua test_hardened.lua
lua breakage_suite/test_context_loss.lua
# ... (full list in README.md). Env: CALYX_STRICT_MODE, CALYX_REDIS_HOST/PORT, CALYX_SQLITE_PATH.
```

Never format or lint `calyx_bundle.lua` directly: it is generated by `lua bundler.lua`
(the header is a generation timestamp, not a parse problem — the file is simply
a build artifact). Fix formatting in `core/*.lua`, then regenerate.

## 3. Acceptance criteria for the next (behavioral) pass

Lint/format cleanup and behavior fixes ship separately. Each behavioral fix needs a
regression test that **fails before and passes after**:

1. Colon/dot calling convention (`fsm:can()` / `fsm:is()` class).
2. False-success effect results (`db:exec` ignored return, unknown effects reported as executed).
3. Event-name collisions (reserved names like `send`, unvalidated names).

Graduation items for `.luacheckrc`: scope `212`/`213` off global once callback
arities are pinned; revisit `W211`/`W311` in demos vs core separately.
